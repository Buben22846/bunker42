# BUNKER 42 — сетевой MVP

Веб-приложение для игры «Бункер» с друзьями: каждый участник подключается со своего телефона или компьютера. Самостоятельный дизайн и небольшой собственный набор карт. Это не копия кода/контента Shelter42 и не готовый публичный игровой сервис.

## Быстрый запуск

1. Установите **Node.js 22 или новее** (рекомендуется Node.js 24 LTS).
2. Распакуйте архив и откройте терминал в папке `bunker42`, где находится `package.json`.
3. Выполните:

```sh
npm start
```

4. Откройте в браузере **http://localhost:3000**.

Устанавливать зависимости (`npm install`) не требуется: сервер использует стандартную библиотеку Node.js, интерфейс — обычные HTML/CSS/JavaScript. Альтернативный запуск без npm:

```sh
node server.mjs
```

Не открывайте `public/index.html` двойным щелчком: приложению нужен сервер. Остановить его можно `Ctrl+C`.

## Как сыграть

1. Введите имя и создайте комнату.
2. Отправьте друзьям ссылку кнопкой «Пригласить» либо код комнаты.
3. Соберите **4–16 игроков**. Каждый нажимает «Я готов».
4. Создатель может выбрать катастрофу и профиль бункера или оставить случайный выбор. Нажмите «Начать партию».
5. Изучите катастрофу, три условия выживания и свои закрытые карты. На телефоне условия доступны в раскрываемом блоке над игровыми действиями.
6. В первом раунде откройте профессию; в следующих — по одной закрытой характеристике. На выступление 30 секунд, затем обсуждение.
7. Голосуйте в назначенных раундах. Можно менять выбор до дедлайна. Без действительного голоса система голосует против самого бездействовавшего игрока.
8. Спецкарта доступна только в указанное окно. В финале состав победителей фиксируется, затем три формальные проверки определяют результат команды.

Общайтесь за одним столом или в отдельном голосовом чате — встроенной аудиосвязи нет. Создатель комнаты не может менять чужие карты или вручную назначать выбывших.

## Телефоны в одной Wi-Fi сети

`localhost` на телефоне обозначает **сам телефон**, а не ваш компьютер.

1. Узнайте локальный IPv4 компьютера: Windows — `ipconfig`; Linux — `hostname -I`; macOS — настройки сети.
2. На всех устройствах откройте адрес вида `http://192.168.1.50:3000` (замените IP своим).
3. Приглашайте друзей со страницы, открытой по этому адресу: скопированная ссылка будет использовать правильный сервер.
4. Если соединение не устанавливается, проверьте разрешение входящих подключений к Node.js/порту 3000 в **частной** сети. Гостевой Wi-Fi может изолировать устройства друг от друга.

Компьютер должен оставаться включённым, терминал — открытым. Для теста нескольких игроков на одном компьютере используйте отдельные профили браузера: вкладки одного профиля делят доступ к одному персонажу.

## Сохранение и повторный вход

- Сервер сохраняет комнаты в `data/rooms.json`. При обновлении страницы карты не раздаются заново, а таймер не перезапускается.
- Доступ к персонажу хранится в `localStorage` браузера отдельно для каждой комнаты. Не очищайте данные сайта во время игры.
- После перезапуска сервер догоняет истёкшие дедлайны. Это может автоматически раскрыть карты/засчитать голоса, пока сервер был выключен; таймеры не ставятся на паузу.
- Ссылка приглашения содержит только код комнаты, не секрет игрока. Секреты не включены в архив.
- В случае повреждённого сохранения сервер останавливается, не перезаписывая файл. Сделайте резервную копию и восстановите корректный файл; автоматического восстановления повреждённого JSON нет.
- Резервные копии делайте при остановленном сервере. Не публикуйте `rooms.json`: он содержит закрытые игровые данные.

## Проверки

```sh
npm test
```

Включены базовые, независимые QA и нормативные регрессионные тесты. Дополнительный HTTP-harness использует локальные порты **3101 и 3103**: они должны быть свободны. Фикстуры хранятся во временной папке ОС и удаляются. Тесты не требуют интернета.

Результаты проверенной сборки и границы проверки: `docs/QA_SUMMARY.md`. Браузерная автоматизация использовала Playwright в среде разработки; для обычного запуска приложения он не нужен и зависимости для него не поставляются.

## Структура кода

```text
server.mjs                 HTTP API, авторизация доступа к игроку, файлы и сохранение
engine.mjs                 серверные состояния, таймеры, раскрытие, голоса, эффекты
content.mjs                карточки, катастрофы, профили и валидация пакета
public/index.html          оболочка страницы и правила
public/app.js              интерфейс, HTTP polling, состояние соединения
public/style.css           тёмный адаптивный дизайн
public/favicon.svg         собственная иконка
test/                     автоматические тесты
docs/GAME_RULES.md         исходная спецификация v1.0
docs/APPROVED_DECISIONS.md утверждённое дополнение к правилам
data/                     создаваемое сервером приватное сохранение
```

Изменять оформление удобно в `public/style.css`, интерфейс — в `public/app.js`. Игровые решения должны проверяться на сервере, а не только скрытием кнопок. После правок выполняйте тесты.

Пак: 96 обычных карточек (16 на категорию), 16 уникальных ID спецкарт с 6 типами эффектов, 3 катастрофы, 2 профиля и 10 карт бункера. Некоторые спецкарты имеют одинаковые названия, но разные ID — это намеренные экземпляры. Багаж с тегом ресурса сам по себе не меняет уровень ресурса: уровень меняют только явные эффекты.

## Параметры сервера

По умолчанию: `PORT=3000`, `HOST=0.0.0.0`, `DATA_DIR=./data` относительно папки приложения. Сведения из `PORT/HOST/DATA_DIR` — переменные окружения, не `.env`-файл.

Linux/macOS:

```sh
PORT=3000 HOST=0.0.0.0 DATA_DIR=/path/to/private-data node server.mjs
```

Windows PowerShell:

```powershell
$env:PORT="3000"
$env:DATA_DIR="C:\bunker42-data"
node server.mjs
```

## Размещение для друзей через интернет

Нужен хостинг с **долго работающим Node.js-процессом и постоянным диском**. Статический хостинг (например, публикация только HTML) не подходит.

- Запуск: `npm start`; одна реплика/один процесс приложения.
- Хранение: постоянный volume, путь которого передан в `DATA_DIR`.
- Интерфейс и `/api` должны открываться на одном домене; настройте HTTPS.
- При reverse proxy он должен задавать/перезаписывать `X-Forwarded-Proto` по фактическому протоколу внешнего подключения и сохранять корректный Host. Конфигурация TLS/proxy не проверялась в этой сборке.
- Не размещайте несколько копий сервера, одновременно записывающих один JSON-файл.

При необходимости можно использовать приложенные `Dockerfile` и `compose.yaml`. Это инструкция, не уже выполненный деплой. Docker при сборке скачивает базовый образ и требует интернет. Публичный домен, хостинг и возможные расходы выбираются отдельно.

## Ограничения MVP

- Синхронизация — polling примерно раз в секунду, не WebSocket.
- JSON-хранилище подходит для небольшой доверенной компании, но не заменяет транзакционную БД, crash-durability и нагрузочные испытания. При сбое записи возможна разница между ответом и состоянием в памяти.
- Нет регистрации, восстановления секрета на другом устройстве, публичного каталога комнат, редактора карт, интегрированной аудиосвязи, ИИ-финала и установки как PWA.
- До 500 сохранённых комнат на сервер; автоматической очистки старых комнат нет. Для полного сброса остановите сервер и безопасно уберите `rooms.json` — все комнаты будут удалены.
- Нет отдельного события `player_reconnected`: polling восстанавливает экран, но не моделирует полноценные connect/disconnect-сессии.
- Реальные Safari/Firefox, мобильные устройства и публичная эксплуатация не прошли отдельную приёмку. Предназначение этой версии — тестовые игры с друзьями.
